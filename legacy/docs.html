Quickstart

A free workspace includes the whole platform. The first project is usually a folder, a notebook, and a few sources — add the rest as you need it.

  1. Create a workspace. Pick a name you'll recognize later, like the study or lab you're working on.
  2. Add your first files. Upload a CSV, a notebook, or a PDF. Spindle detects common formats and previews them in place.
  3. Open the lab. Start RStudio, JupyterLab, VS Code, or a terminal on the same files.
  4. Run a search. Save results and citations into the project instead of a browser history.

The basics

Workspaces & files

Each project has its own file tree. Files, notes, results, and conversations stay with it, so handing a project to someone else means sharing one place rather than a pile of links.

PROJECT LAYOUTEXAMPLE
/coastal-resilience
  /data           measurements, exports
  /notebooks      R and Python analysis
  /sources        papers and search results
  /results        figures and tables
  project-log.md  decisions and handoffs

Lab sessions

Lab environments boot connected to the project files. Use RStudio for statistics, JupyterLab for notebooks, VS Code for code, or a terminal for everything else. Teammates can share kernels and leave comments in context.

Sources

Local search

Academic mode queries BASE, arXiv, Crossref, Semantic Scholar, and OpenAlex. Basic mode uses Mojeek, Brave, and DuckDuckGo. Both run through a SearXNG instance hosted alongside Spindle, so results and notes stay inside the project.

Automations

Describe a repeated step in plain language or write a cron job yourself. Either way, the automation lives with the project it serves and can update files, notes, or results.
